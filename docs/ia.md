# Uso de IA en el Proyecto

Este documento registra el uso de herramientas de inteligencia artificial durante el desarrollo del proyecto, con fines de transparencia académica y gobernanza arquitectónica. Para cada intervención se detalla el alcance aceptado, los criterios de rechazo frente a la erosión del sistema, y el nivel de supervisión humana, asegurando que las decisiones de diseño y control permanezcan siempre bajo la potestad exclusiva del equipo de desarrollo.

## Herramientas utilizadas

- **Claude** (Anthropic) - Modelado arquitectónico, revisión de contratos, análisis de seguridad y redacción de ADRs.
- **ChatGPT / Gemini** (OpenAI / Google) - Comparativa de estilos, validación de esquemas y soporte de ideación.
- **Claude Code** (Anthropic) - Agente de programación en terminal, usado directamente sobre el repositorio para leer el código, editar archivos, ejecutar pruebas (`pytest`, `flutter analyze`, `flutter test`) y preparar commits. Se emplea en la implementación de funciones del backend y del cliente Flutter (p. ej., tema claro/oscuro), la sincronización del contrato OpenAPI, el modelo C4 vigente y la actualización de ADR y documentación (incluido este registro).
- **Codex** (OpenAI) - Implementación, pruebas reproducibles y verificación de evidencias del repositorio.
- **GitHub Copilot** (Microsoft) - Asistencia de autocompletado en el entorno de desarrollo local.

## Criterio del equipo sobre el uso de IA y Control de Erosión

El equipo utiliza la inteligencia artificial como un copiloto de desarrollo acelerado, pero mantiene un control estricto sobre la integridad del código y la arquitectura del sistema:

1. **Cero Erosión de Dependencias:** Toda sugerencia de código es filtrada para evitar la adición no autorizada de paquetes de terceros en `requirements.txt` que comprometan la restricción C5 o introduzcan vulnerabilidades.
2. **Respeto a los Límites de Contexto:** Se verifica continuamente que el código autogenerado respete la arquitectura hexagonal y el aislamiento de módulos definido desde la Semana 6.
3. **Verificación por Defecto / Mutación:** Ninguna función autogenerada se da por correcta sin una prueba unitaria que garantice su fallo cuando el algoritmo o regla de negocio se rompe intencionalmente.
